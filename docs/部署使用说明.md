# ZLGCAN 桥接（zlgcan_bridge）部署使用说明

## 一、功能概述

ZLG USBCAN-2E-U 为厂商私有协议设备（非 SocketCAN）。本桥接程序通过 `libzlgcan.so` 收发 ZLG 帧，
转发到 SocketCAN `can0`（vcan 类型），使 FSD `can_interface` 节点与 hil_test 测试框架无需任何修改即可使用真实 ZLG 硬件。

```
真实VCU ⇄ CAN总线(500k) ⇄ USBCAN-2E-U ⇄ libzlgcan.so ⇄ zlgcan_bridge ⇄ SocketCAN can0(vcan)
                                                                    ├─ FSD can_interface（默认 can0）
                                                                    └─ hil_test -i can0（real 语义）
```

注意：`vcan0` 保留给纯仿真（sim 模式），桥接固定使用 `can0`。

## 二、部署步骤

1. 放置厂商 SDK：将 Linux 版 `libzlgcan.so` 放入 `zlgcan_bridge/lib/`（脚本自动注入 `LD_LIBRARY_PATH`）。
2. 编译（首次启动时也会自动编译）：
   ```bash
   cd zlgcan_bridge
   cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
   cmake --build build -j$(nproc)
   ```
3. 插入 USBCAN-2E-U 并确认设备枚举正常（`lsusb` 周立功设备）。

## 三、启停与状态

```bash
./scripts/start_bridge.sh start      # 后台启动（日志 zlgcan_bridge/bridge.log，PID bridge.pid）
./scripts/start_bridge.sh status     # 查看状态
./scripts/start_bridge.sh stop       # 停止
./scripts/start_bridge.sh selftest   # 虚拟设备自测（type=99，无需硬件，验证 SDK 加载）
./scripts/start_bridge.sh            # 前台运行（调试）
```

配置文件 `config/bridge_config.yaml`：设备类型（USBCAN-2E-U=21）、通道、波特率（默认 500000）、
SocketCAN 接口（默认 can0）、统计/重连周期等；支持 `--lib`、`-i`、`-v` 命令行覆盖。

## 四、接入 hil_test

```bash
./hil_test/scripts/hil_test.sh -l L1 -i can0 --bridge   # 临时启用桥接（自动创建 can0 并启停桥接）
```

或在 `hil_test/config/hil_test.yaml` 将 `can.bridge.enabled` 设为 `true`，此后 `-i can0` 自动走桥接：

```yaml
can:
  bridge:
    enabled: true
```

桥接模式下：
- `can0` 不存在时由 `start_bridge.sh` 自动创建（vcan 类型，需 sudo 免密或输入密码）；
- **桥接日志自动收进本次 hil_test 批次目录** `hil_test/logs/latest/bridge.log`（与节点日志统一管理），脚本启动时打印路径，可 `tail -f hil_test/logs/latest/bridge.log` 实时查看 ZLG 设备收发统计/掉线重连；独立启动桥接时日志在 `zlgcan_bridge/bridge.log`；
- 测试结束后自动停止桥接进程；
- L2 看门狗/心跳等用例语义与真实 VCU 总线一致（0x210/0x501，10Hz，500k）。

## 五、FSD 接入

`can_interface` 默认 `can_device: "can0"`，无需修改；只要桥接在 FSD 启动前（或运行中）就绪即可。
桥接对掉线自动重连，SocketCAN 侧 socket 保持打开，FSD 节点不中断。

## 六、常见问题

- `dlopen(libzlgcan.so) 失败`：确认已将 SDK 放入 `lib/`，且与系统架构一致（x86_64/aarch64）。
- `ZCAN_OpenDevice 失败`：检查设备是否被占用（同一设备仅一个进程可打开）、设备类型号是否为 21。
- 掉线频繁：`ZCAN_IsDeviceOnLine != STATUS_ONLINE` 触发重连，查看 `bridge.log` 统计段排查总线负载与波特率。
- 心跳无 0x501：真实 VCU 未上电或波特率不一致（默认 500k，可改 `zlgcan.baud_rate`）。
